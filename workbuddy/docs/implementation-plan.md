# 单专家实施与验收

## 产品范围

当前以 main 的单专家「自媒体获客运营专家」切入，专家层拆为按需读取的原生技能模块，保留其工具脚本、workflow、参考资料和素材。已有视频素材加工由本包直接完成；从零完整制作接收用户成片，或交给当前真实可调用的 WorkBuddy 制作专家/技能。不打包 content-producer、IT engineer、sales-cs crew 或 OpenClaw 引擎。

这也是小贝官方的 VIP Club 获客入口。市场三条问题突出十账号 DNA、小红书原生卡片生成发布、公众号诊断；首次交付、服务咨询或缺少会员凭证时展示掌柜二维码与权益说明。默认 relay 沿用 https://relay.openclaw-for-business.com，不新增平台专属服务。

保留 BD、IR、四声分析、追爆、记录、校准、卡片与公共技能。视频号整包、OSBI、sales-cs-manager 和 xiaobei-operations 不纳入。其他 Camoufox 工具裁剪后同步修订制作、发布交付、复盘、登录和参考文档；不允许留下不可调用的命令。具体清单在 skill-inventory.md。

## 已实现的适配

1. 从原 main/public 源文件受控导出，记录源文件与产物校验值，保留嵌套工具结构和共享库；源变动会阻止旧包构建。
2. 提供统一命令入口和 wrapper 映射，隔离安装包、依赖缓存、平台登录态与用户工作空间。
3. 数据脚本改用明确工作空间，ASR 共享库改为包内路径，卡片改用 Chromium，API 代理不读取 Camoufox 配置。
4. 保留各技能 Python/Node/FFmpeg 依赖的初始化路径。CLI 检查宿主 Node/Python/Bash，不依赖 OpenClaw 安装脚本。
5. X/TikTok/微博使用明确授权的 API 文件导入，在临时目录在线核验身份后才落库；快手保留 HTTP 扫码/短信。TikTok 写能力仍受完整会话材料约束。
6. 配置以用户私有文件输入，不在包中预置凭据或虚构 MCP 地址。平台请求仍客户端直发，已有 relay 负责对应签名/计算/代理服务。
7. main SOUL/IDENTITY 嵌入官方规范支持的 Agent 系统提示词；掌柜二维码随包携带并提供 contact 命令。空的公共 AIGC 占位文件不导出，实际生成模块及三供应商入口保留。
8. 整体排除公众号自动采集技能和主题工具的采集脚本，公众号诊断、对标、DNA 与排版均使用用户提供的内容；主题 wrapper 读取本地 HTML。专家简介覆盖多平台获客运营，市场 README 列出各平台与支撑工具的能力边界；能力不足时在 AGENTS.md、实际专家提示词和市场 README 引导下载完整版。

## 本地验证与平台验收

包结构、资源完整性、原生 SQLite 记录/校准、跨工作空间写入、视频加工与卡片出图在 test/workbuddy 验证；解压 ZIP 后重新运行，确保不依赖仓库绝对路径。

已在本机隔离 Linux 目录完成全量依赖安装、四平台共享运行库离线探测与 deck 转换流程。WorkBuddy 市场实机、不同操作系统、平台内首次安装与实号仍需验收。检查：

- 导入 ZIP 后中文职业、头像、三个快捷问题与 README 正确，主入口能按任务读原生技能，资源与脚本路径可访问。
- 首次任务中 doctor 和按需依赖初始化成功，缺失基础运行时的错误可见。Windows 需要可执行 Bash 的环境；当前仅做本机 Linux 验证。
- 真实产品找十个同赛道账号，检查账号筛选、样本证据与独立 DNA；真实小红书卡片确认后发布并记录；真实公众号诊断交付文章证据与三个优先行动。
- 首次交付和缺少 OFB_KEY 时验证会员介绍、二维码展示和私有配置；已有会员不会重复推销，价格和权益不混同于 WorkBuddy 模型额度。
- 卡片、发布记录、指标、校准和 BD 记录实际落工作空间；切换工作空间不混用数据，更新专家后保留用户状态。
- 有授权和凭据时逐项验证 API、relay、平台读取/发布/互动；没有凭据时不能把本地验证当作实号成功。先做读取验收，实际写入限于明确授权的账号、内容和对象。
- 已裁剪的 Camoufox 命令不能回退调用宿主旧工具；缺失步骤只接受用户资料或本次真实可用的 WorkBuddy 工具。
- 有真实专家/子任务调用工具才交接视频制作或并行 Council；没有时交付 Brief 或明确标注同会话四声分析。不能由“同一市场都有专家”推定可以自动调用。

## 后续阶段

先在单专家里验证安装和运营闭环，再按需求补 WorkBuddy 连接器的托管运行时、账号授权与服务接入。连接器的 CLI Node/Python 托管与专家脚本的宿主环境要求是两件事，不能直接承诺一键运行所有外部工具。

完整 Buddy 应用建立在已验收的专家、技能、连接器之上，届时再整合 content-producer 或更完整的界面与协作流程。当前不发布市场资产、不部署 relay、不自动操作真实社媒账号。
