# 起号、定位梳理与老号接手 Workflow

新号起号、账号定位梳理、内容支柱搭建、默认 `dna-0` 初始化、老号接手走这个 Workflow。独立账号对标走 `account-benchmark.md`。

## 入口判断

用户说以下话时走：

| 意图 | 典型说法 | 处理 |
| --- | --- | --- |
| 新号起号 | “我想做个公众号，从零开始” | 业务信息检查 -> 定位梳理 -> 初始 `dna-0` |
| 定位梳理 | “梳理一下内容方向”“搭建内容支柱” | 定位梳理 -> 必要时更新 `dna-0` |
| 老号接手 | “这个号以后你来接手”“账号还行，先按原风格写” | 整理用户的老号样本 -> 建立或更新 `dna-0` |
| 老号诊断 | “帮我看看这个号还有没有救”“给我们号把个脉” | 整理用户的老号样本 -> 判断延续或重建 |
| 默认 DNA 初始化 | “初始化默认 DNA” | 按新号 / 老号路径建立 `dna-0` |

## 从零开始打造新号

### 初始化原则

1. 默认 DNA 固定为 `dna-0`。
2. 除 `account-benchmark.md` 分流的对标样本外，用户不指定 DNA 时，参考文章和后续新增样本默认累积到 `dna-0`。
3. `dna-0` 可以由参考账号、参考文章、用户想法和 `business_knowledge.md` 共同形成，不绑定单一账号名。
4. 若 `wx_mp/dna/dna-0/dna-0.dna.md` 已存在，不覆盖重建；新资料按 `style-dna.md` 的更新流程进入。
5. 独立对标样本不直接写入 `dna-0`，必须走 `account-benchmark.md` 并进入独立 DNA；用户明确采纳的局部规则可通过局部 DNA 融合更新 `dna-0`。

### Step 1 - 业务信息检查

先读取 Workspace 根目录的 `business_knowledge.md`，检查三项关键信息：

| 关键信息 | 最低要求 |
| --- | --- |
| 产品 / 服务概括 | 能说明卖什么、解决什么问题、核心差异 |
| 收费项目 | 能说明主要收费方式、产品或价格区间 |
| 目标受众 | 能说明具体人群、痛点、使用场景 |

任一项为空、仅有占位符或互相矛盾时，先与用户补齐。不要凭空编造。

用户思路不清晰、多个定位方向难以取舍或商业假设冲突时，调用顶层 `council` 技能辅助梳理；`council` 不收纳进公众号专家包。

更新 `business_knowledge.md` 前必须征得用户同意，并遵守 Workspace 根 `AGENTS.md` 的治理规则。

### Step 2 - 定位梳理

新号起号、老号重建和用户要求“梳理定位 / 内容支柱”时都必须执行。已有清晰定位且用户只要求接手写作时，可以基于现有账号样本校验定位，不重新发起完整讨论。

#### 输入

1. `business_knowledge.md` 中的产品、服务、收费、受众和红线。
2. 用户目标：IP 信任、获客、销售、社群、流量主或专栏。
3. 已有账号样本和表现线索（如有）。
4. 用户提供的对标方向（如有）。

#### 输出

1. **定位句**：我帮助[目标读者]，用[方法/内容承诺]解决[具体痛点]，让他们获得[理想结果]。
2. **账号承诺**：读者为什么关注、持续看什么、什么时候转化。
3. **内容支柱**：3-5 个，分别承接搜索、信任、故事、证明、转化或留存。
4. **关键词宇宙**：类目词、痛点词、场景词、人群词、商业词。
5. **选题库雏形**：每个支柱至少 5 个候选选题。
6. **约束与风险**：合规边界、宣传限制、版权、品牌语气、产能。

用户思路不清、多个方向冲突或商业假设不一致时，先用少量问题澄清；仍难判断时调用顶层 `council` 技能辅助决策。

### Step 3 - 新号初始 DNA 路径判断

先区分两种“参考”：

- 用户明确要把参考账号或文章作为默认 DNA 的初始来源 -> 走下方路径 A / B / C，产物进入 `dna-0`。
- 用户只是要分析参考账号、比较风格差异或寻找可借鉴模式 -> 走 `account-benchmark.md`，对标样本进入独立 DNA，不直接写入 `dna-0`。
- 意图不明确时，先向用户确认“是纳入默认 DNA，还是只做对标比较”。

#### 路径 A：用户提供了参考账号或参考文章

1. 按 `style-dna.md` 获取样本：
   - 正文、文档和封面：读取用户提供的材料，整理为 profiler 输入
   - 公众号名或文章链接：只作出处，请用户补充实际正文和封面
   - 本地文本：直接输入 profiler
2. 目标 DNA 固定为 `dna-0`。
3. 每篇生成 report。
4. 运行 `wechat-style-profiler build --dna-id dna-0`，生成 DNA 文档与 template。
5. 把选题、标题、结构、语气、可复用规则和例外发送用户确认。
6. 用户调整意见按 `style-dna.md` 的“用户输入转译”更新到 `dna-0`。

用户没有明确权重时，所有 report 默认权重为 1。

#### 路径 B：用户暂无参考，但业务信息完整

Agent 基于 `business_knowledge.md` 提炼搜索关键词，建议用户到微信公众号搜索头部或表现较好的账号。

关键词至少覆盖：

- 类目词：行业、产品、服务类型
- 痛点词：用户具体问题、替代方案、决策难点
- 场景词：使用时机、使用场所、触发条件
- 人群词：身份、角色、行业、消费能力
- 商业词：收费、方案、测评、避坑、选择

给用户的搜索建议必须说明：

1. 优先找读者相近、承诺清晰、近期仍活跃的账号。
2. 优先选择转发和评论信号强的文章；阅读量只作次要参考。
3. 账号级初始参考建议收集 10 篇文章；用户明确提供单篇或少量样本时仍可建立 `dna-0`，但必须标注覆盖不足，不得称为账号级稳定 DNA。
4. 本版不提供公众号自动采集。用户找到参考后提供正文、封面和数据线索，Agent 基于这些材料提炼。

用户补充文章内容后，回到路径 A；账号名和链接不能代替正文。

#### 路径 C：用户拒绝外部参考或已有明确想法

1. 结合 `business_knowledge.md`、用户定位、目标受众、变现方式和用户思路，提炼 `dna-0`。
2. Agent 直接按 17 维框架编写：

```text
wx_mp/dna/dna-0/dna-0.dna.md
wx_mp/dna/dna-0/dna-0.template.md
```

3. DNA 文档必须标明来源是“业务信息 + 用户指定方向”，没有文章样本统计。
4. 能确定的规则写为执行要求；未确定维度写“待校准”，不得虚构单篇证据。
5. Template 仍必须给出可执行的分段生产结构；不能只有抽象定位词。
6. 将 DNA 摘要和待校准点发给用户确认，再按用户意见转译修订。

后续获得真实文章样本时，按 `style-dna.md` 生成 report 并更新 `dna-0`。

### Step 4 - 默认 DNA 落盘

完成路径 A / B / C 后，确认以下文件存在且互相一致：

```text
wx_mp/dna/dna-0/reports/
wx_mp/dna/dna-0/covers/
wx_mp/dna/dna-0/dna-0.dna.md
wx_mp/dna/dna-0/dna-0.template.md
```

检查要求：

- DNA 文档说明样本来源、覆盖数量、权重、例外和待校准点。
- Template 能由 DNA 文档推导，直接指导段落任务、标题类型、句式、语气和 CTA。
- 用户输入已转译为维度级规则，不是原话堆积。
- 对标样本 report 不混入 `dna-0`；用户采纳后，只有转译后的规则通过局部 DNA 融合进入 `dna-0`。

## 老号接手

### Step 1 - 整理老号样本

1. 请用户提供近期代表文章的正文、封面和必要截图；支持粘贴或本地文档，建议以 30 篇为分析上限。
2. 只有公众号名或链接时补问内容；建议 10 篇，不足时先分析已提供的样本并注明限制。
3. 按 style-dna.md 整理正文与封面，去重、标记材料缺口；不自动抓取，不将样本当作完整发布历史。

### Step 2A：账号基本可用，用户让 Agent 接手

用户对账号目前的情况基本满意，目的是让Agent接手，延续目前账号的风格。

1. 将老号文章生成属于 `dna-0` 的 DNA report。
2. 若 `dna-0` 不存在：运行 `wechat-style-profiler build --dna-id dna-0`，建立默认 DNA 文档与 template。
3. 若 `dna-0` 已存在：新增 report 后按 `style-dna.md` 更新 `dna-0`，不覆盖重建。
4. 将DNA 摘要、可复用规则和待校准点发给用户确认。
5. 用户意见按“用户输入转译”更新 `dna-0`，后续内容生产默认使用 `dna-0`。

### Step 2B：用户认为账号不太可用，需要推倒重来

1. 基于`Step 1`拿到的样本提炼出常用作者署名、核心卖点、选题方向、账号名称、核心CTA等基础信息，将这些信息与用户确认。
2. 结合上述信息，走 `从零开始打造新号` 流程
3. 如果 `business_knowledge.md` 不全，可以先从step A的样本中提取，不足的信息与用户讨论

### 老号诊断速查

先分析用户已提供的正文、封面和数据，再补问缺失信息。可判断内容支柱、质量、调性、选题和标题；发布时间和频率只依据用户提供的真实记录。

按失败环节倒推：

| 现象 | 可能原因 | 修法 |
| --- | --- | --- |
| 曝光低 | 信号不清、赛道漂移、合规风险、内容弱 | 收紧主页、保持垂直、查风险、更一致 |
| 有曝光打开低 | 标题弱、选题泛、读者不匹配 | 重写标题、强化钩子、更具体 |
| 打开完读低 | 开头慢、语言端着、没故事张力 | 调整开头、加冲突和例子 |
| 阅读收藏低 | 不够实用、缺清单模板流程 | 加可带走资产、表格、步骤 |
| 阅读评论低 | 没明确问题、没身份张力 | 问一个跟读者处境有关的具体问题 |
| 互动关注低 | 有用但账号承诺不清 | 强化简介、系列承诺、开场白 |
| 关注转化弱 | 行动引导不清或太早销售 | 明确下一步、FAQ、诊断入口 |
